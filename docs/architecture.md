# Tag Toolbox — Architecture

Contributor-facing map: modules, files, the verified engine seams everything is built on, and the design rules that keep the plugin safe to extend. Engine facts below were verified against installed UE source (5.8, with 5.0 spot checks) — not guessed.

## Modules

| Module | Type | Purpose |
|--------|------|---------|
| `TagToolbox` | Runtime | `UTagToolboxSettings` only — the styles registry and plugin options. No gameplay behavior; nothing ships in a cooked game. |
| `TagToolboxEditor` | Editor | All features: customizations, picker, Browser, Audit, comment tint. Everything lives in `Private/`. |

## Verified engine seams

- **Property-type registration is silently last-wins.** Identifier-less `RegisterCustomPropertyTypeLayout` overwrites the type's single BaseCallback with no error, and `Unregister` clears rather than restores. GameplayTagsEditor registers its own customization *inside the OnPostEngineInit broadcast*, so ours registers **one tick later** (`GetOnPostEngineInit` → `SetTimerForNextTick`); hot-reload/late-load paths register immediately. The pill yields to Paper2DPlus (reflective probe of `bColorizeGameplayTagPickers`); containers have no contender.
- **Blueprint variable metadata flows to compiled properties.** `FBPVariableDescription::MetaDataArray` is copied onto both member and function-local `FProperty`s by the kismet compiler, and `SetBlueprintVariableMetaData` additionally stamps the skeleton + generated classes immediately. The tag picker resolves `Categories` through `UGameplayTagsManager::GetCategoriesMetaFromPropertyHandle`, which walks parent handles, array inner / map key properties, and owner-function metadata — never read the bare `GetMetaData("Categories")`; it silently unfilters inherited scopes.
- **Saved tags are Asset Registry searchable names.** `FGameplayTag`/`FGameplayTagContainer` serialization calls `MarkSearchableName` on save; `IAssetRegistry::GetReferencers(FAssetIdentifier(FGameplayTag::StaticStruct(), TagName), …, EDependencyCategory::SearchableName)` answers "who uses this tag" instantly with zero loads. Exact names only — hierarchy queries must expand child names themselves. Editor-only data; cooked registries filter it.
- **The engine picker's rows are sealed.** `SGameplayTagPicker`'s row generation, row style, and text color are private with no hooks — colored rows/favorites REQUIRE a from-scratch tree (this repo's `STagToolboxTagPicker`). Its public `Filter`/`PropertyHandle` args remain useful for hosting it as the container multi-select editor.
- **Comment widgets can't be recolored by subclassing.** `SGraphNodeComment` binds its body/title colors to non-virtual methods and `TitleBar` is private — hence the factory-stamp approach (which also renders for users without the plugin once assets are saved).
- **Engine rename never fixes assets.** `RenameTagInINI` recursively renames the dictionary and appends a redirect, but performs no referencer check and no resave — the fix-up gap TASK-1's headline candidate fills.

### v0.2 destructive-flow characterization (U2)

Verified 2026-08-20 against UE 5.8 — source reads plus a scratch headless probe run in the dev host (`TagDebtProbe.Characterization`; probe deleted after the findings landed here). These are the preflight facts the rename/delete/resave flows are built on.

1. **`AddNewGameplayTagToINI` failure surfaces (source + probe).** Empty string, `ShouldImportTagsFromINI()==false`, invalid tag string (notification carries the engine's `FixedString` suggestion), and already-a-dictionary-tag each return `false` with a notification; the duplicate case logs at Error severity. A named `TagSourceName` that does not exist yet is created via `FindOrAddTagSource(..., TagList)` under `Config/Tags/`. Adding a tag whose name matches a settings redirect old-name first deletes that redirect.
2. **Rename mechanics (source).** `RenameTagInINI(bRenameChildren=true)` renames each direct dictionary descendant recursively FIRST (each child writes its own redirect), then: `DeleteTagRedirector(new)` + `DeleteTagRedirector(old)` — both search ONLY `UGameplayTagsSettings` — then adds the new tag into the OLD tag's source, deletes the old row, and appends the redirect to the old tag's owning `UGameplayTagsList` (falling back to the settings list only when the old tag has no editor data). Renaming onto an already-defined target is a silent native merge (no confirm anywhere in the engine). A pre-existing `A→B` redirect living in a NON-settings list is invisible to the rename's redirect cleanup — chain handling is the caller's job.
3. **Re-running a completed rename (probe + source).** For a leaf tag the re-run is a benign no-op: `GetTagEditorData(old)` resolves THROUGH the redirect, so the redirect row stays in its owning list (no settings duplicate materialized in the probe). But for a SUBTREE the same redirect resolution walks the already-renamed children into X→X self-renames, and an X→X rename DELETES the child's row and writes a self-redirect — destructive. Recovery after a partial rename therefore must never call `RenameTagInINI` again: detect "old name already redirects to the requested target" in the plan phase and skip straight to the resave stage.
4. **Delete mechanics (source).** `DeleteTagsFromINI` refuses per tag with a notification when Asset Registry referencers exist (checked per tag, including implicit parents that would die with it); deleting an explicit parent whose children remain keeps the tag alive implicitly ("still exists implicitly due to children") — children are never deleted; deleting an implicit tag refuses ("remove children manually"); a tag name matching a settings redirect old-name deletes the REDIRECT instead of the tag and reports success. The bulk form logs instead of showing notifications and refreshes the tree once at the end.
5. **Loaded referencers hold the OLD name (probe).** After a rename, a loaded referencer's in-memory `FGameplayTag` still carries the old name, and resaving it WITHOUT a reload writes the old name back to disk (searchable-name deps confirmed unchanged). A clean `UPackageTools::ReloadPackages` (`AssumePositive`) re-resolves through the redirect and a subsequent resave writes the new name — the reload→resave recipe is proven. A DIRTY package: `AssumeNegative` makes the reload report failure with the package skipped (edits intact, still dirty); `AssumePositive` clears the dirty flag and DISCARDS the unsaved edits while reporting success. The resave service must therefore SAVE opted-in dirty packages first (the old name it writes is covered by the redirect), then reload, then resave — and never reload a dirty package it hasn't just saved.
6. **Rollback is two-tier (probe).** Restoring a loose `Config/Tags` ini's bytes and calling `EditorRefreshGameplayTagTree()` is a COMPLETE rollback: tree reconstruction re-`LoadConfig`s loose lists from disk and `FGameplayTagRedirectors` rebuilds from them (old tag back, new tag gone, redirect gone). The default settings list does NOT reload from disk on refresh — and even `GConfig->LoadFile` + `Settings->ReloadConfig()` + refresh left the redirect live in the probe (defaultconfig hierarchy caching), so settings-owned mutations CANNOT be reliably rolled back in-session. Detection: after restore + refresh, probe `RequestGameplayTag(oldName)` — a still-redirecting answer means in-memory divergence → surface the blocking "restart before saving anything" prompt. (`RequestGameplayTag` applies redirects before dictionary lookup — "redirects take priority, even if the tag itself may exist".)
7. **`FGameplayTagQuery` properties DO mark searchable names (probe).** A saved query's tags appear as SearchableName dependencies alongside plain tag and container properties, and query-held tags re-resolve through redirects on load — queries are fully covered by scan, rename preview, and resave fix-up. Not an un-fixable store.
8. **Environment note (probe side effect).** With an in-editor source-control provider active (the dev host had git integration on), the engine's `GameplayTagsUpdateSourceControl` marks newly created tag inis for add in source control — flows that create or delete tag sources should expect provider interactions even before any package saves.

## Design rules

1. **Presentation, never authority.** Styles, filters, tints, and audits change what designers see and pick — never what tags mean, and never at runtime in a cooked game.
2. **Registry is an override list.** Empty by default; every consumer keeps a stock fallback. Never seed `FGameplayTag` rows in a CDO constructor (tag-manager init order). `TArray` of entries, never a tag-keyed `TMap` in config (UE-230676).
3. **Commits mirror the engine exactly.** Property writes use the same transaction + formatted-string / per-object-values shapes as the engine widgets, so undo and multi-edit behave identically.
4. **Never name a local or parameter `Tag` inside an `SWidget` subclass** — it shadows `SWidget::Tag` and fails as C4458 under warnings-as-errors (this bit twice on day one; use `InTag`/`NodeTag`).
5. **Widgets triggered from their own click handlers defer their rebuilds** one tick (`RegisterActiveTimer`) — a synchronous `ClearChildren` destroys the widget whose handler is still on the stack.
6. **Menu-hosted pickers are selection-only** and wrapped in the RMB guard; never push a context menu from an auto-dismissing menu host.
7. **Config writes never flush manually** on interactive paths (`GConfig->Set*` alone is durable; a manual flush rewrites the whole ini).
8. **Read paths never load assets; explicit fix-up actions load and resave under confirm.** The audit, References pane, and usage counts stay registry-metadata-only, and their blind spots (C++ call sites, string-typed tags, unsaved edits) stay documented rather than papered over. The rename fix-up and resave actions are the sanctioned loaders: explicit gestures, a consent dialog naming every package (dirty ones opt-in only), and per-package outcome reports — never a load hidden behind a refresh.
9. **Destructive tag flows follow the characterization facts** (the "v0.2 destructive-flow characterization" section above): rollback only before any package saves, save-first for opted-in dirty packages, reload-before-resave, skip-to-resave recovery instead of re-running the engine rename, chain collapse never chaining, and persist-verified redirect writes with in-memory revert. A change to any of those flows re-verifies against the numbered facts first.
